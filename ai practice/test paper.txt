H2 Computing (9569/02) Preliminary Examination: Practical Task (Advanced)
Task Title: Enterprise Asset & Inter-Departmental Booking Platform (EquipHub Pro)

Total Marks: 30 marks

Suggested Time: 1 hour 15 minutes

Background Context
The basic EquipHub system has been upgraded to EquipHub Pro to support inter-departmental equipment cross-borrowing, detailed historical audit logs, and complex inventory reporting across multiple school campuses.

Instead of a single collection, the database now utilizes a relational data model within MongoDB, consisting of two linked collections: equipment and bookings. You must design the backend socket server to process multi-stage aggregation pipelines and support flexible, multi-parameter search requests from the client.

Database Schema Specification
The database name is ccadb_pro.

1. equipment Collection Schema:

JSON
{
  "item_id": "AV001",
  "name": "Wireless Microphone System",
  "category": "Audio-Visual",
  "campus": "North",
  "total_stock": 10,
  "specs": {
    "frequency": "UHF",
    "battery_life_hours": 8
  }
}
2. bookings Collection Schema:

JSON
{
  "booking_id": "BK-2026-0001",
  "item_id": "AV001",
  "borrower_cca": "Symphonic Band",
  "qty_borrowed": 3,
  "status": "ACTIVE",
  "return_date": "2026-07-25"
}
(Note: An item can have multiple active or completed bookings. "status" can be "ACTIVE" or "RETURNED").

Task 2.2: Server Aggregation & Multi-Parameter Queries (12 marks)
Create the backend server program named server_adv.py. Configure a TCP socket server listening on 127.0.0.1:12345.

The server must receive pipe-delimited (|) commands and execute the following complex queries using pymongo:

SEARCH|category|campus|min_battery

Behavior: A flexible multi-parameter search. Any parameter can be passed as "ANY", which means that field should not be filtered.

Logic: Construct a dynamic MongoDB filter query. If min_battery is not "ANY", query the nested field "specs.battery_life_hours" for values greater than or equal to the specified integer.

Return: A JSON-formatted string representing a list of matching items (exclude the _id field). If no items match, return "RES_EMPTY".

AUDIT_STOCK|item_id

Behavior: Calculates the current available stock of a specific item by checking how many units are currently out on active loan.

Logic: Use the MongoDB Aggregation Framework (aggregate()):

Match the document in equipment by item_id.

Perform a $lookup (left outer join) with the bookings collection where equipment.item_id equals bookings.item_id.

Filter or $unwind the joined bookings to only consider those where "status" is "ACTIVE".

Calculate available_stock = total_stock - (sum of qty_borrowed from active bookings).

Return: Formatted string: "[AV001] Wireless Microphone System | Total: 10 | On Loan: 3 | Available: 7". If item_id does not exist, return "ERR_NOT_FOUND".

OVERDUE_BY_CCA|target_cca

Behavior: Finds all equipment currently borrowed by a specific CCA where the "return_date" is strictly before today's date (2026-07-17) AND "status" is "ACTIVE".

Logic: Query bookings using $match, then use $lookup to join with equipment to retrieve the item's name and campus.

Return: Formatted string listing the Booking ID, Item Name, Campus, and Return Date. If no overdue items exist for that CCA, return "NO_OVERDUE".

EXIT

Close the client connection cleanly.
